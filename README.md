# Logicbroker Agent

An adaptive RAG (Retrieval-Augmented Generation) agent for Logicbroker customer support. It answers questions about the Logicbroker platform by searching a knowledge base of support articles and API documentation, grading retrieval quality, and generating citation-grounded responses with hallucination detection.

**Live demo:** https://logicbroker-agent-production.up.railway.app

## Architecture

The agent uses a LangGraph state machine implementing an adaptive RAG pipeline:

```
START → classify → retrieve → grade_documents
                                     │
                              (conditional routing)
                              ┌──────┴──────┐
                          generate     rewrite_query
                              │              │
                    check_hallucination ←── retrieve (retry loop, max 2)
                              │
                             END
```

### Pipeline stages

1. **Classify** — Routes the query into one of 6 categories (`onboarding`, `order-lifecycle`, `edi-technical`, `api-integration`, `platform-config`, `general`) using Claude with structured output
2. **Retrieve** — Fetches relevant chunks from ChromaDB (vector search) and optionally the knowledge graph. API-related categories trigger dual retrieval from both API docs and KB articles
3. **Grade** — Each retrieved chunk is graded as relevant/irrelevant by Claude. If all chunks are irrelevant, the query is rewritten and retrieval retried (up to 2 times)
4. **Generate** — Produces a citation-grounded answer using only the relevant chunks. Citations use `[N]` notation linking to source articles
5. **Hallucination check** — Verifies the generated answer is grounded in the retrieved context. Ungrounded answers are replaced with a decline response

### Retrieval system

The agent uses two complementary retrieval systems:

- **ChromaDB vector store** — 1,635 chunks from ~272 KB articles and API docs, embedded with `all-MiniLM-L6-v2` (local, no API key needed). Chunks are 1,000 characters with 200-character overlap.
- **Knowledge graph** — A graph of Logicbroker concepts and relationships, queried via hybrid keyword + embedding ranking with community detection (Louvain clustering). KG results are injected as synthetic high-confidence chunks for `order-lifecycle`, `onboarding`, and `edi-technical` queries.

### Anti-hallucination strategy

Two layers of grounding:

1. **Citation enforcement** — The generation prompt requires every claim to cite a source. Answers without relevant documents return a decline response instead of fabricating.
2. **Hallucination gate** — A dedicated verification node checks the answer against retrieved context. Ungrounded answers with unsupported claims are caught and replaced.

## Data sources

| Source | Type | Count | Ingestion |
|--------|------|-------|-----------|
| [Logicbroker Support KB](https://support.logicbroker.com) | Support articles | ~272 articles | `scraper.py` |
| [Logicbroker REST API](https://commerceapi.io/swagger/docs/v3) | OpenAPI v3 spec | 15 endpoint groups | `api_docs_parser.py` |
| Knowledge graph | Concept relationships | ~200+ nodes | `build_kg.py` / `build_kg_v2.py` |

Scraped and parsed data lives in `data/`:
- `data/kb_articles/` — Markdown files with YAML frontmatter (title, URL, category)
- `data/api_docs/` — Per-tag markdown files from the OpenAPI spec
- `data/knowledge_graph_v2.json` — Node/edge graph with predicates and context
- `data/chroma_db/` — ChromaDB persistent storage (generated by indexer)
- `data/kg_cache/` — Cached node/community embeddings (generated at runtime)

## Tech stack

| Layer | Technology |
|-------|-----------|
| Agent framework | [LangGraph](https://langchain-ai.github.io/langgraph/) + [LangChain](https://python.langchain.com/) |
| LLM | Claude Sonnet (`claude-sonnet-4-6` via `langchain-anthropic`) |
| Embeddings (vector) | `all-MiniLM-L6-v2` (local, via `sentence-transformers`) |
| Embeddings (KG) | `text-embedding-3-small` (OpenAI, for KG community/node embeddings) |
| Vector store | [ChromaDB](https://www.trychroma.com/) (local persistent) |
| Graph analysis | [NetworkX](https://networkx.org/) with Louvain community detection |
| Backend | [FastAPI](https://fastapi.tiangolo.com/) + [Uvicorn](https://www.uvicorn.org/) |
| Frontend | [React 18](https://react.dev/) + [Vite](https://vitejs.dev/) |
| Deployment | [Railway](https://railway.com/) or [Fly.io](https://fly.io/) via Docker |

## Project structure

```
src/logicbroker_agent/
  server.py          FastAPI app with SSE streaming, health endpoint, lifespan warmup
  graph.py           LangGraph state machine — classify, retrieve, grade, generate, hallucination check
  retriever.py       ChromaDB vector retriever + knowledge graph retriever
  indexer.py         Document chunking and ChromaDB indexing pipeline
  kg_enhanced.py     Enhanced KG retriever with community detection and hybrid ranking
  kg_openai.py       Alternative KG retriever using OpenAI embeddings
  api_docs_parser.py OpenAPI v3 spec parser → per-tag markdown files
  scraper.py         Logicbroker KB article scraper → markdown files
  cli.py             CLI interface (single query, interactive REPL, JSON output)

web/
  src/App.jsx        React SPA — 3-column layout with history, Q&A, and agent trace terminal
  vite.config.js     Vite config with API proxy to backend

data/                Pre-scraped KB articles, API docs, KG, and cached embeddings
scripts/             Benchmark and analysis scripts
tests/               Evaluation suite (12 eval cases + 15 benchmark queries)
```

## Getting started

### Prerequisites

- Python 3.10+
- Node.js 20+ (for frontend build)
- An [Anthropic API key](https://console.anthropic.com/) (`ANTHROPIC_API_KEY`)
- An [OpenAI API key](https://platform.openai.com/) (`OPENAI_API_KEY`) — for KG embeddings only

### Local development

```bash
# Clone and install
git clone https://github.com/ilikerustoo/logicbroker-agent.git
cd logicbroker-agent
python -m venv .venv
source .venv/bin/activate
pip install -e .

# Set environment variables
export ANTHROPIC_API_KEY=sk-ant-...
export OPENAI_API_KEY=sk-...

# Index documents into ChromaDB (first time only)
python -m logicbroker_agent.indexer

# Build the frontend
cd web && npm ci && npm run build && cd ..

# Run the server
uvicorn logicbroker_agent.server:app --reload --port 8000
```

Open http://localhost:8000 in your browser.

### CLI usage

```bash
# Single query
logicbroker-agent "How do I set up EDI?"

# Verbose mode (shows classification, grading, retrieval details)
logicbroker-agent -v "Order API endpoints?"

# JSON output
logicbroker-agent --json --pretty "How do returns work?"

# Interactive REPL
logicbroker-agent

# Pipe from stdin
echo "How does the portal work?" | logicbroker-agent
```

### Re-scraping data

If you need to refresh the KB articles or API docs:

```bash
# Scrape KB articles from support.logicbroker.com
python -m logicbroker_agent.scraper

# Parse OpenAPI spec from commerceapi.io
python -m logicbroker_agent.api_docs_parser

# Rebuild the ChromaDB index
python -m logicbroker_agent.indexer
```

## API

### `POST /api/ask`

Sends a query and returns a Server-Sent Events (SSE) stream.

**Request body:**
```json
{ "query": "How do I configure webhooks?" }
```

**SSE event types:**

| Event | Data | Description |
|-------|------|-------------|
| `trace` | `{"text": "...", "kind": "step"}` | Pipeline progress. Kinds: `shell`, `dim`, `step`, `result`, `ok` |
| `answer` | `{"text": "...", "sources": [...], "grounded": true}` | Final answer with citations |
| `error` | `{"text": "..."}` | Error message |
| `done` | `{}` | Stream complete |

### `GET /api/health`

Returns server health and warmup status.

```json
{ "status": "ok", "version": "0.1.2", "warm": true }
```

## Deployment

### Docker

The Dockerfile is a multi-stage build:
1. **Frontend stage** — `node:20-slim`, builds the React app with Vite
2. **Backend stage** — `python:3.12-slim`, installs Python deps, runs the indexer at build time (bakes the ChromaDB collection into the image), copies the built frontend

```bash
docker build -t logicbroker-agent .
docker run -p 8000:8000 \
  -e ANTHROPIC_API_KEY=sk-ant-... \
  -e OPENAI_API_KEY=sk-... \
  logicbroker-agent
```

### Railway

The project includes a `railway.json` config:

```json
{
  "build": { "builder": "DOCKERFILE", "dockerfilePath": "Dockerfile" },
  "deploy": {
    "healthcheckPath": "/api/health",
    "healthcheckTimeout": 120,
    "restartPolicyType": "ON_FAILURE",
    "restartPolicyMaxRetries": 3
  }
```

To deploy:
1. Create a Railway project and connect your GitHub repo
2. Set the deploy branch (e.g., `railway-deploy`)
3. Add environment variables: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`
4. Railway auto-detects the Dockerfile and deploys

Railway keeps containers always-on by default (no cold start). The 120s health check timeout accommodates the initial model weight loading.

### Fly.io

The project includes a `fly.toml` config targeting the `sjc` (San Jose) region with shared-cpu-1x and 1GB RAM.

```bash
fly launch
fly secrets set ANTHROPIC_API_KEY=sk-ant-...
fly secrets set OPENAI_API_KEY=sk-...
fly deploy
```

Note: Fly's auto-stop behavior (`min_machines_running = 0`) causes ~96s cold starts due to torch/sentence_transformers imports. Set `min_machines_running = 1` to keep a machine warm, or use Railway for always-on behavior.

## Evaluation

### Eval suite (`tests/test_eval.py`)

12 test cases covering all 6 query categories plus edge cases. Runs the full agent pipeline and checks:

| Metric | Threshold |
|--------|-----------|
| Classification accuracy | >= 80% |
| Grounding rate | >= 70% |
| Source retrieval | >= 90% |
| Term coverage | >= 70% (each case hits >= 50% of expected terms) |
| Overall pass rate | >= 70% |

```bash
# Run the eval suite (requires ANTHROPIC_API_KEY, slow)
pytest tests/test_eval.py -m eval -v
```

### Benchmark (`scripts/benchmark_e2e.py`)

15 queries across 5 categories (relational, factual, API, troubleshooting, conceptual) with fact-checking against expected answers.

```bash
python scripts/benchmark_e2e.py -v
python scripts/benchmark_e2e.py --json --output results.json
python scripts/benchmark_e2e.py --category api  # filter by category
```

## Frontend

The web UI is a React SPA with a Dracula-inspired dark theme. Three-column layout:

- **Left rail** — Query history
- **Center** — Question input with sample query chips + answer panel with inline citations
- **Right** — Agent trace terminal showing real-time pipeline progress (classify → retrieve → grade → generate → hallucination check)

SSE streaming shows each pipeline step as it executes. The terminal displays color-coded trace events matching the agent's internal state transitions.

Sample queries available in the UI:
- "How do I configure a new retailer connection?"
- "What EDI document types does Logicbroker support?"
- "How do I set up order acknowledgements?"
- "Explain the shipment API endpoints"
